## 1. Method, and what this pass could not do

* Every finding was re-read from its JSON record (never from the `.md` summary) and given one
  disposition: **applied** (with before → after), **rejected** (with the reason), or **open**
  (with the measured cause). A rejection is a decision, not a dismissal: each one names the file
  or gate that made the fix the wrong call for this pass.
* Write scope is the brief's: `src/**`, this file, `package.json`. That is why the whole
  `README.md` / `README.zh-CN.md` / `docs/ATTRIBUTION.md` class of findings is **rejected as
  out of scope** rather than fixed — they are real defects (several are critical) and each one is
  a `REJECTED` row in §4 naming the exact line and the measured number the docs owner needs.
  `scripts/verify/**` is likewise final-review's write scope, so every finding whose fix is a
  gate change is **routed**, never silently satisfied.
* **No finding was satisfied by bending the product.** Where a correct fix flips an assertion
  that pins the CURRENT (defective) state, the flip is listed in §2 as a handoff and the gate is
  left honestly red for final-review to re-point.
* Measurements taken for this pass (not retyped from any report): the per-plane contour-loop
  budget before/after the vessel handoff (my own GLB parser + the shipped `extractContours`);
  the WCAG contrast ratios of every token candidate; the dimmed-row blend at four opacities; the
  plate frame-vs-artwork correlation for all 15 plates; the shipped course/tube/meta counts; the
  audit-facts census before and after.
* **Not verifiable in this session, and therefore not claimed:** anything browser-visible
  (`verify:acceptance`, `verify:audit`, `verify:browser`), and the two gates that shell out to a
  child process (`verify:anatomy`, `verify:imaging-fit` — the sandbox denies piped child stdio,
  so they exit 1 with 0 verdicts; see §2 and §6).
